# Архитектура сервисов: новости, EDMI и чат

Документ описывает текущую связку сервисов вокруг Tradematic: сбор новостей, промежуточную обработку, построение базы знаний и работу AI-чата.

## Общая схема

```text
news parser
    ↓
news_dataset.csv
    ↓
EDMI processing
    ↓
processed_events.csv
    ↓
asset analysis + market brief
    ↓
RAGPipe index build
    ↓
Tradematic AI chat
```

Параллельная идея системы:

```text
сырой новостной фон ───────────────┐
                                   ↓
                            RAG база знаний
                                   ↑
агрегированные события EDMI ───────┘
```

Чат работает с общей базой знаний, куда попадают и сырые новости, и результаты обработки EDMI.

## 1. Парсер новостей

Парсер расположен в:

```text
services/news_aggregator
```

Он отвечает за сбор сырого новостного фона:

```text
источники новостей
    ↓
RSS / HTML страницы
    ↓
парсинг title, text, url, source, published_at
    ↓
дедупликация на уровне датасета
    ↓
services/news_aggregator/data/news_dataset.csv
```

Парсер обходит список новостных источников, извлекает статьи, чистит HTML, достаёт заголовок, текст, ссылку, источник и дату публикации. Если полноценный текст статьи недоступен, используются данные из RSS summary или chunks.

Для сетевых сбоев добавлены retry-механизмы с backoff, чтобы временный обрыв сети не останавливал весь сбор.

Результат парсера:

```text
services/news_aggregator/data/news_dataset.csv
```

## 2. EDMI processing

EDMI — это модуль обработки новостного фона.

Основной поток:

```text
news_dataset.csv
    ↓
построчное чтение CSV
    ↓
валидация новости
    ↓
дедупликация по URL/text hash
    ↓
NER
    ↓
embedding
    ↓
поиск похожих новостей
    ↓
агрегация в события
    ↓
LLM-классификация
    ↓
оценка связи событие → актив
    ↓
расчёт impact
    ↓
processed_events.csv
```

CSV читается потоково, без полной загрузки файла в память. Это позволяет обрабатывать большие новостные датасеты.

EDMI не должен анализировать каждую новость как отдельный независимый факт. Он группирует похожие новости в события. Например, несколько публикаций от разных источников про одно решение ЦБ должны объединяться в одно событие.

LLM используется для смысловых задач:

- классификация типа события;
- определение релевантности событие → актив;
- генерация объяснения для пользователя;
- подготовка рыночной сводки.

Код отвечает за объективные вычисления:

- дедупликация;
- поиск похожих новостей;
- агрегация событий;
- расчёт рыночной дельты;
- расчёт impact.

## 3. Построение базы знаний

После обработки строится база знаний для чата. Она собирается из нескольких слоёв:

```text
news_dataset.csv
processed_events.csv
rag_index.csv
asset_analysis.json / .md
market_brief.json / .md
    ↓
RAG indexing
    ↓
main/scripts/datasets/ragpipe/
```

В базу знаний попадает не только сырой новостной фон, но и обработанные события, аналитика по активам и рыночная сводка.

Это нужно, чтобы пользователь мог спрашивать как про общий новостной фон, так и про влияние событий на активы.

## 4. Ollama

Ollama используется в двух ролях.

Первая роль — LLM внутри пайплайна EDMI:

```text
EDMI событие
    ↓
Ollama llama3.1
    ↓
тип события / релевантность / объяснение
```

Вторая роль — модель для чата:

```text
вопрос пользователя
    ↓
RAG retrieval
    ↓
контекст из ragpipe index
    ↓
Ollama / tradematic-analyst
    ↓
ответ
```

Модель не обучается через fine-tuning в классическом смысле. Актуальные знания попадают в неё через RAG: индекс обновляется после парсинга и процессинга, а Ollama отвечает на основе найденного контекста.

## 5. Чат в Tradematic

Чат встроен в авторизованную панель Tradematic.

UI-файлы:

```text
templates/panel.html
templates/ragpipe_chat.html
templates/chat.html
static/js/ragpipe-chat.js
static/css/panel-styles.css
```

Роуты:

```text
/panel/
/chat/
/api/ragpipe/chat/
```

Доступ защищён:

- `/panel/` доступен только после авторизации;
- `/chat/` доступен только после авторизации;
- `/api/ragpipe/chat/` доступен только после авторизации и только через POST.

Поток вопроса пользователя:

```text
пользователь в Tradematic
    ↓
кнопка AI чат
    ↓
POST /chat/
    ↓
Django view chat_api
    ↓
EDMI API /ragpipe/chat
    ↓
RAGPipe ищет контекст
    ↓
Ollama генерирует ответ
    ↓
ответ возвращается в Tradematic UI
```

Кнопка чата находится на странице панели и появляется только для авторизованного пользователя.

## 6. Промежуточные файлы

Основные артефакты пайплайна лежат в:

```text
main/scripts/datasets/
```

Файлы:

- `news_dataset.csv` — сырые новости от парсера;
- `processed_events.csv` — обработанные события EDMI;
- `rag_index.csv` — RAG-представление обработанных событий;
- `rag_training.jsonl` — JSONL с контекстом для аналитики/RAG;
- `asset_analysis.json` — структурный анализ по активам;
- `asset_analysis.md` — человекочитаемый анализ по активам;
- `market_brief.json` — структурная рыночная сводка;
- `market_brief.md` — человекочитаемая рыночная сводка;
- `ragpipe/` — индекс базы знаний для чата.

## 7. Docker-связка

В Docker Compose система собирается из следующих частей:

```text
django / Tradematic UI
edmi-api
pipeline
news parser
redis
postgres / pgvector
ollama
open-webui
```

`pipeline` запускает полный процесс:

1. собрать новости;
2. скопировать CSV в `main/scripts/datasets`;
3. обработать новости через EDMI;
4. построить базовый RAG;
5. создать или обновить Ollama model;
6. сделать анализ активов;
7. сделать market brief;
8. построить RAGPipe index.

После этого Tradematic UI и чат используют подготовленную базу знаний.

## Итоговая роль компонентов

Парсер собирает факты.

EDMI превращает новости в события и аналитику.

RAGPipe делает из новостей и событий базу знаний.

Ollama отвечает на вопросы на основе найденного контекста.

Tradematic показывает чат авторизованному пользователю.
